版本：2026-11-28 · 依据：方案 3.1/5.4/5.5、交底说明三.2

## 一、原始目录对象（现有数据，不改名）

## 二、API 输出对象（新增，只在内存里组装）

### ProblemRef

| 字段 | 类型 | 规则 |
|---|---|---|
| `source` | `'ybt' \| 'pset'` | pid 在 3001–3079 → `ybt`，其余 → `pset`（预设，可改） |
| `id` | string | `String(pid)` |
| `key` | string | **`'ybt' + pid`，与现网进度键逐字一致**，不许改前缀 |

改键等于把 `studypage.done` 里所有记录清空，这是硬约束。

### ProblemSummary

**按目录条目生成：1446 条，同一 `pid` 允许多条。** 禁止按 pid 去重后丢弃，否则 b5/1 的 1414、b6/1 的 1839、b2/2 的 1176/1178/1183 会从对应章节消失。

| 字段 | 类型 | 来源 |
|---|---|---|
| `ref` | ProblemRef | 计算；同一 pid 的两条 `ref.key` 相同，靠 `groupId + lessonNo` 区分位置 |
| `title` | string | 原始 `title` |
| `groupId` | string | 所属章 `id`（= 原单里的 `chapterId`，改名以对齐 `contracts.js` 注释） |
| `lessonNo` | number | 所属课 `no` |
| `type` | `'example' \| 'practice'` | `kind` 映射：`ex → example`，`pr → practice` |
| `acceptCount` / `submitCount` | number | `ac` / `sub` 原值 |
| `timeLimitMs` / `memoryLimitKb` | number | `time` / `mem` 原值；API 透出、UI 不渲染 |
| `difficulty` | `number \| null` | 现数据没有难度字段，一律 `null` |
| `done` | boolean | 由 `getProgress` 注入，**不在目录快照里** |

### CatalogSnapshot

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | `1` | 字面量 1，改动要另立批次 |
| `chapters` | Chapter[] | 原样（深拷贝） |
| `problems` | ProblemSummary[] | 展开视图，长度 = **目录条目数 1446**，同 pid 可出现多条 |
| `stats` | `{entries, unique, examples, practices}` | 1446 / **1432（主数字）** / 243 / 1203 |

题数口径（架构师已定）：页面总量、进度分母、`stats.unique` 用 **1432**；章卡/课卡内部按**条目**统计；`admin.html` 双显示。

### ProgressSnapshot

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | `1` | |
| `studentKey` | string | 未登录 `'guest'`（待架构师确认） |
| `doneKeys` | string[] | 副本，元素形如 `ybt1001` |
| `completedCount` | number | `doneKeys` 与目录交集的数量（防止脏键虚高） |

### JudgeResult

| 字段 | 类型 | 说明 |
|---|---|---|
| `requestId` | string | 调用方生成，回传比对 |
| `problemKey` | string | `ybt<pid>` |
| `transportOk` | boolean | HTTP 层是否拿到 2xx JSON |
| `status` | 见下 | **7 个枚举**（`LK.contracts.judgeStatus`） |
| `passed` | boolean | 只有 `accepted` 为 true |
| `compileMessage` | string | 编译日志；空串不是 `undefined` |
| `runMessage` | string | 运行段说明（耗时/退出码/错误） |
| `stdout` | string | 程序输出原文 |
| `durationMs` / `memoryKb` | number | 服务端值，缺省 0 |
| `raw` | object | 服务端原始响应，UI 不依赖 |

`status` 枚举与现网判题服务的对应：

| 现网 `judgeStatus` | 新 `status` |
|---|---|
| `OK` 且输出与样例一致 | `accepted` |
| `OK` 且输出不一致 | `wrong_answer` |
| `CE` | `compile_error` |
| `RE` | `runtime_error` |
| `TLE` | `time_limit` |
| `MLE` | `runtime_error`（`runMessage` 保留 `MLE` 原文） |
| `OLE` | `runtime_error`（`runMessage` 保留 `OLE` 原文） |
| HTTP 401 / 票据失效 | 抛 `AUTH_REQUIRED` |
| 请求失败、超时、跨域被拦 | `network_error` |
| 服务 5xx / 无响应体 | `judge_unavailable` |

现网服务只有 `OK/CE/TLE/MLE/OLE/RE` 六个值（`判题服务_部署记录_2026-11-22.md:64`），`wrong_answer` 由客户端比对样例得出，**不是**服务端返回。

## 三、判题接口现状（客户端要照着迁，不改语义）

```text
POST {JUDGE_URL}/ticket   body {token}            → {ticket}
POST {JUDGE_URL}/run      header X-Judge-Ticket
                          body {code, stdin, lang} → {compile:{ok,log,time}, run:{stdout,time,exit}, judgeStatus}
```

- 一次只跑一组 stdin，没有多测试点；`lang` 固定 `cpp14`。
- 请求超时：换票 5s、运行 12s（`预览_DevC布局.html:1266,1287`）。
- 同源时 `JUDGE_URL='/judge'`，`file://` 回落 `http://59.110.125.57/judge`（`1244-1246`）。
- 迁移后这些数值原样保留为常量，不改。

## 四、已由架构师拍板的 3 个字段问题

1. `catalog.time/mem`：原始数据保留、API 透出成 `timeLimitMs/memoryLimitKb`、**UI 不渲染**。
2. `open`：保留并原样透出，**不加新判断**（全量实测为 `true`）。
3. `brand`：原始数据保留，但 **API 不透出**，避免和 `data/config.js` 的 `SITE.brand` 混淆。
4. 13 个重复题号：**数据不动**，`ProblemSummary` 按条目生成（1446 条），`unique 1432` 只进 `stats`；跨章重复必须能在各自章节看到，禁止静默丢弃。
