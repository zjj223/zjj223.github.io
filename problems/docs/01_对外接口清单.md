## 二、`shared/` 没有、由我层内实现（不改 shared）

| 函数 | 层内实现 | 理由 |
|---|---|---|
| `wan(n)` 万位 | `problems/api.js` 私有 | `LK.utils` 只有 `thousands`（千分位），题库要「1.29万」这种显示 |
| `today()` | `LK.utils.isoDate(new Date())` 包一层 | 少写一次 `new Date()`，不新增契约 |
| `guest` | `problems/progress.js` 常量 `GUEST_KEY='guest'` | 架构师明确不进 shared |
| `refToPid(ref)` | `String(ref).replace(/^ybt/,'')` → `Number` | `routes.url` 只收数字 |
| `ybt<pid>` 组装 | `'ybt' + pid` | 进度键硬约束，不能改前缀 |

## 三、事件（名字和必填字段照抄 contracts）

| 事件 | 必填 detail 字段 | 我何时发 |
|---|---|---|
| `lk:problems:progress-changed` | `schemaVersion, eventId, at, studentKey, problemKey, done` | `markDone` 成功后 |
| `lk:judge:finished` | `schemaVersion, eventId, at, requestId, problemKey, result` | `evaluate` 结束（无论成功失败） |

不发「目录就绪」事件：`getCatalog()` 同步返回。`detail` 一律用 `LK.contracts.makeEvent(name, extra)` 生成，不自造 `eventId`。

## 四、我提供给 UI / 游戏的 API（`problems/api.js`，schemaVersion=1）

```js
LK.problems.getCatalog() -> CatalogSnapshot          // 同步，深拷贝
LK.problems.getChapter(chapterId:string) -> Chapter|null
LK.problems.getLesson(chapterId:string, lessonNo:number) -> Lesson|null
LK.problems.getProblem(ref:ProblemRef|string) -> Problem|null
LK.problems.getProblemUrl(ref:ProblemRef, opts?:{g?:string,l?:number}) -> string   // 内部走 LK.routes.url('problem',{pid})
LK.problems.getProgress() -> ProgressSnapshot        // studentKey 由 LK.auth.getSession() 推导
LK.problems.markDone(problemKey:string, meta?:{source:string}) -> ProgressSnapshot
LK.problems.evaluate(req:EvaluateRequest) -> Promise<JudgeResult>
LK.problems.getStats() -> {entries:number, unique:number, examples:number, practices:number}
```

说明：
- `getProgress()` 不再收 `studentKey` 参数——会话从 `LK.auth` 取，未登录记 `'guest'`；这样 UI 少传一个必错参数。
- `getProblemUrl` 保留（方案 5.4 要求），但**不新增 shared 路由函数**，实现是 `LK.routes.url` 的薄包装。
- `getStats().unique` 是唯一题号（1432），`entries` 是目录条目（1446），两个数都出，主数字用 `unique`。
