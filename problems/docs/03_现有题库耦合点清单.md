## 四、结论：哪些字段是真消费、哪些是死的

**真消费（迁移必须原样保留）**：`chapters / lessons / problems / pid / title / kind / ac / sub`；章的 `id / name`；课的 `no / name / kp`。

**死字段或近乎死的（可保留但不渲染）**：

1. `brand`：0 处读取。页头品牌走的是 `data/config.js` 的 `SITE.brand`，不是 `CATALOG.brand`——两套 brand 并存，别混。
2. `catalog.time` / `catalog.mem`：0 个目录消费方。预览页显示的时间/内存来自 ybt/pset 题面数据（单位分别是毫秒/KB，除以 1000 和 1024 后显示）。
3. `open`：只有 `学习台.html:410` 一处判断，且全库实测取值全是 `true`，条件永不成立。

**统计口径陷阱**：目录 1446 条 = 1432 个唯一题号 + 14 条重复（13 个题号）。所有页面都用「遍历条目」算题数，所以首页、练习题库、学习台报的题数都会比唯一题号多 14。这是既有口径差异，不是新 bug。

## 六、必须先钉死的 5 个危险点

1. **键前缀统一是 `ybt`**：ybt 题与 pset 题都生成 `'ybt'+pid`（预览页 `2888`、`2917`；学习台 `230`；home.js 多处）。新 `ProblemRef.source` 只能靠 pid 区间反推（3001–3079 → ybt），不能改键。
2. **空课/空章会打崩学习台**：`学习台.html:278` 的 `g.lessons.reduce` 和 `280` 的 `g.lessons.filter`、`365` 的 `g.lessons.forEach` 都没有 `|| []` 兜底；其余页面（练习题库、排行榜、home.js）全都写了 `(g.lessons || [])`。已登记的 D-01 就是这条。收敛后的准确行号是 **278 / 280 / 365**；`341`（有 `if (!g) return []`）、`354`（有 `g ?`）、`357`（在 g 存在的分支内）已具备防护。
3. **题面裸拼 HTML**：`2887-2900`、`2915-2928` 把 `desc/hin/hout` 直接塞进 `<p>`，题面含 `<`、`&` 会坏版或注入。
4. **合并顺序静默吞题**：`2918` 的 `if (PROBLEMS[key]) return;` 让 pset 同键题被丢弃且不报错。现在两套 pid 不相交，但这依赖数据巧合。
5. **两套 brand / 两套 catalog 同名**：`app.js:147-199` 的 `SITE.catalog` 是**商品目录**（球价、时装价），与题库 `CATALOG` 完全无关。命名冲突，迁移文档里必须写清，避免有人把两者接错。
